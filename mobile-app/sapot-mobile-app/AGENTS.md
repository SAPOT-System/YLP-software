# AGENTS.md — mobile-app/sapot-mobile-app

React Native (Expo) mobile app — SAPOT's primary end-user client for offline-capable messaging, calls, GPS sharing, and SMS. See the root `AGENTS.md` for repo-wide conventions and `CLAUDE.md` in this directory for architecture, DI wiring, and decision rules — this file only covers workflow/tooling not already there.

## Development Workflow

- Package manager: **pnpm** (`pnpm-lock.yaml`, pinned `packageManager` field). Install: `pnpm install`.
- Dev server: `pnpm dev` (sets `APP_VARIANT=development`) or `pnpm start`.
- Note: this project's own `CLAUDE.md` and its `testAll` script body invoke `npm run ...` internally even though pnpm is the declared manager — both toolchains need to be available locally; prefer `pnpm run <script>` for anything you invoke directly.

## Build

- Native prebuild: `pnpm prebuild` (`expo prebuild -p android --clean` + Android signing setup)
- Android run: `pnpm android` / iOS run: `pnpm ios`
- EAS cloud builds: `pnpm android:dev`, `pnpm android:prev`, `pnpm android:prod`
- OTA updates: `pnpm update:dev`, `pnpm update:prev`, `pnpm update:prod`

## Test

- `pnpm test` — Jest with `jest-expo` preset (config inline in `package.json`); global mocks (WatermelonDB, TCP sockets, WebRTC, Zeroconf, Expo modules) live in `jest-setup.js`.
- `pnpm typecheck` — `tsc --noEmit`.
- `pnpm testAll` — test + typecheck + lint + `expo-doctor`; treat this as the completion gate, not just `pnpm test`.

## Lint / Format

- `pnpm lint` — ESLint (`eslint.config.js`, flat config).
- No formatter (Prettier or otherwise) is configured — match surrounding style by hand.

## Framework Expectations

- New features go under `features/<name>/{services,repositories,hooks,components,types.ts,index.ts}` — don't invent a different structure.
- Services are wired through `MainContainer`/`AuthContainer` (manual DI), not instantiated ad hoc in components — see `CLAUDE.md` for construction-order details before adding a new service.
- Local persistence is WatermelonDB (SQLite); schema changes go through `features/shared/database/schema.ts` **and** a corresponding entry in `features/shared/database/migrations.ts` — never bump the schema version without a matching migration.
- `any` is banned outside test mocks; `unknown` only at trust boundaries, narrowed before use.

## Do Not Edit Manually

- `app.config.ts` version fields (`version`, `extra.displayVersion`) — synced by `scripts/set-version.js`; hand edits will be overwritten or cause a version/tag mismatch.
- `pnpm-lock.yaml` — regenerate via `pnpm install`, don't hand-edit.
- `/ios` and `android/` — generated by `expo prebuild` (gitignored); don't hand-edit generated native project files, change the Expo config/plugins instead.

## Common Pitfalls

- Treating `server/` as editable from a mobile-app task — it's read-only reference here (see `CLAUDE.md`); a needed backend change should be flagged, not silently made.
- Skipping the migration entry when bumping the WatermelonDB schema version — existing installs will fail to sync.
- Assuming `granted` permission state for camera/mic/location/notifications — every flow touching these must render distinct UI for `not-asked`, `denied`, and `granted`.
- Leaving a network call without failure handling — every one must catch and surface a user-visible state, never an indefinite spinner or a silently swallowed error.
